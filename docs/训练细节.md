# 五子棋强化学习（AlphaGo Zero 式）

9×9 自由五子棋（默认五连即胜，无禁手）。技术路线：轻量残差 CNN（策略+价值双头）
+ PUCT 蒙特卡洛树搜索 + 纯自对弈迭代训练，全程无人类棋谱。

- 默认棋盘 9×9，可在 `gobang/config.py` 改 `BOARD_SIZE` 或命令行 `--size`（模型会记住架构）
- 网络约 39 万参数，单卡 GTX 1650 即可；自对弈默认 GPU 多进程（自动检测）

## 快速开始

```bash
# 正式训练（细节参数在工作目录的 train.json 里改，不用敲长命令）
uv run python main_train.py

# 用另一份参数文件 / 中断后继续
uv run python main_train.py --config runs/a.json --resume

# 代码内置预设（见 gobang/config.py 的 PRESETS，各用独立 run 目录）
uv run python main_train.py --preset smoke    # 1~2 分钟冒烟，验证整条流水线
uv run python main_train.py --preset quick    # 十几分钟走完 自对弈→训练→晋升 闭环
uv run python main_train.py --preset strong   # 长时间正式训练
# 预设之上仍可单项覆盖，其余参数全部走命令行是不必要的（--help 可查全表）
uv run python main_train.py --preset strong --games 1000

# 人机对战（打开图形窗口，点击落子）
uv run python play.py

# 执白开局、调高 AI 搜索深度
uv run python play.py --you white --sim 600

# 机器 vs 机器观战（tkinter 窗口，支持自动/暂停/单步/调速）
uv run python play.py -o runs/default/latest.pt

# 多局统计（控制台，对手可以是模型路径或 random）
uv run python play.py -o random --games 20

# 纯控制台字符棋盘（不想用窗口时）
uv run python play.py --cli
uv run python play.py -o runs/default/latest.pt --cli --view
```

未训练前直接跑 `play.py` 会提示找不到 `runs/default/best.pt`。

## 参数组织与优先级

细节参数集中在两处，命令行只留真正要动的开关。生效优先级：

**命令行单项 > `--preset` 预设 > 参数文件 > `gobang/config.py` 内置默认**

- `train.json`（工作目录，常量 `DEFAULT_PARAM_FILE`）：主要超参都在这里，直接编辑即可；
  `--config 路径` 换文件，文件不存在则跳过，写了未知键会立即报错（防拼错静默失效）。
  JSON 没有注释，**下划线开头的键当注释**放行（如 `_comment`），不计入「已加载 N 项」。
- `gobang/config.py` 的 `PRESETS`：smoke/quick/strong 整套参数组，各带独立 `run_dir`，
  优先于参数文件，方便冒烟时不被大参数文件拖慢。
- 其余零散常量（GPU 进程上限 `CUDA_WORKER_CAP`、提示/预判搜索深度 `LIGHT_SIM_MIN`/`LIGHT_SIM_DIV`、
  默认模型路径 `DEFAULT_MODEL`、GUI 统计局数 `STATS_GAMES` 等）也收在 `config.py`。
- `meta.json` 会记录本次生效的完整 `config`，复现实验不用截图。
- AMP 混合精度：`use_amp` 开关（默认关）。损失始终在 FP32 计算，数值行为与纯 FP32 一致；
  自对弈推理不走 AMP，对局数据分布不因此改变。实测 GTX 1650 上本模型（64ch/6 块、batch 512）
  开 AMP 反而慢约 3 倍——网络太小、每步是 kernel 发射受限，再叠加 GradScaler 的每步设备同步，
  FP16 的算力优势抵消不了这部分开销。因此默认关闭，仅在你把 `channels`/`blocks`/`batch_size`
  调大、训练变成 GEMM 算力受限后再用 `--amp` 试开。

## 训练日志怎么看

- 终端实时进度：`selfplay: 123/500 [02:41<...]` 为每轮自对弈进度条，
  `eval: x/8` 为晋升评估分片；每轮结束输出一行汇总
  （样本量、损失、局长、评估得分、耗时、预计剩余），并同步落盘 `runs/<dir>/train.log`
- 流水线重叠：每轮训练结束后，「本轮评估」投放到独立 CPU 进程池，同时「下一轮
  自对弈」投放到 GPU 进程池；评估结果延后一轮收集，日志里「评估等待 Xs」正常应
  接近 0（评估 CPU ~80s 藏进训练 GPU ~83-135s 里，训练后不再干等）。评估 CPU 池
  按剩余提交内存自动决定进程数，建不起来时退回串行——GPU 评估与训练抢同一块
  限功率显卡实测双双变慢（1650 训练 83s→142s+），串行反而更快。
  相应地 meta 里的 `t_selfplay` 指本轮收集自对弈结果的剩余等待，`sec` 是整轮节拍。
  评估本身是 CPU 密集活：5060 实测 60 局 sim200 要 ~310s，比一轮自对弈+训练（~190s）
  还长，重叠不完，每轮末尾剩 100~144s 干等（占整轮四成）。用 `--eval-every 3` 摊薄到
  每 3 轮一次，跳过的轮次日志显示「评估 未评」，ce/mse 照常记。
- GPU 占用说明（1650 实测）：训练阶段 util≈94%（算力顶满；冷机 2048 步
  @batch512 约 79s、38.7ms/step，持续负载下降频到 ~66ms/step——这卡是限功率的，
  约 135s 才是常态节拍）；自对弈 4-6 进程即可打满 GPU（util 91-96%，sim64 时
  约 5.2-5.6 局/s），再加进程无收益、≥12 进程会 CUDA OOM（每进程一个上下文，
  显存 4GB）；评估改跑 CPU 后 GPU 全部留给训练与自对弈。`torch.compile` 在
  Windows 缺 MSVC 工具链时不可用；AMP 在无 Tensor Core 的 TU117 上实测慢 3 倍，
  保持关闭。
- `tensorboard --logdir runs/default` 看 ce/mse/评估得分/局长曲线
- 晋升机制：每轮新模型与 best 下 40 局（交替先后手，sim200），
  得分 ≥0.55 才替换 `best.pt`；`--no-eval` 跳过评估直接晋升
- 提交内存预算（16GB RAM 机器实测）：自对弈 CUDA worker 约 0.9GB/进程，评估
  CPU worker 约 0.5GB/进程；评估池延迟到首轮训练后才创建，并按当时剩余提交内存
  自动收缩进程数（放不下就退回串行评估，日志会提示）。若仍遇到
  `WinError 1455 页面文件太小`：把 Windows 页面文件设为系统管理或 ≥20GB，
  或调低 `--workers` / `--eval-workers`
- `Ctrl+C` 安全：checkpoint 原子写（先 .tmp 再替换），每轮完成即写 checkpoint 和
  meta，中断只损失当前轮；正在并行评估的那轮不晋升，续训时会重新评估

## 关键参数

命令行只列常用项，完整清单看 `--help`。默认值来自 `train.json`（下表为内置值）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--config` | `train.json` | 主超参改这里，避免长命令；文件不存在则跳过 |
| `--preset` | 无 | smoke/quick/strong 整套预设，优先于参数文件 |
| `--amp` / `--no-amp` | 关 | GPU 混合精度开关（本模型规模实测更慢，默认关，见上节） |
| `--size` | 9 | 棋盘边长（常量 `BOARD_SIZE`，`play.py` 自动匹配模型架构） |
| `--games` | 500 | 每轮自对弈局数 |
| `--sim` | 128 | 自对弈每步 MCTS 模拟数 |
| `--steps` | 2500 | 每轮训练步数（AdamW，lr 每 `lr_decay_every` 轮乘 `lr_decay`） |
| `--eval-games` | 40 | 晋升评估局数 |
| `--eval-every` | 1 | 每隔几轮评估一次；评估是 CPU 大头，长跑建议 3 |
| `--eval-device` | cpu | 评估进程设备：cpu=独立 CPU 进程池与训练重叠；cuda=与自对弈共享池 |
| `--eval-workers` | 自动 | 评估 CPU 进程数（核数-4） |
| `--workers` | 自动 | 自对弈进程数（GPU 模式封顶 `CUDA_WORKER_CAP`） |
| `--device` / `--sp-device` | auto | 训练/自对弈设备，auto 自动选 cuda |
| `--buffer-window` | 10 | 训练使用的最近轮次数据窗口 |
| `mcts_batch` | 16 | 仅参数文件：一次前向最多塞几个叶子，不是搜索预算（见下节） |

### mcts_batch 必须是 sim 的几分之一（踩坑记录）

`mcts_batch` 只是「一次前向最多塞几个叶子」。若 `mcts_batch >= sim`，整步搜索从头到
尾只有一次批量回传：下降全部停在根节点下、每个可走点各 1 次访问，价值反馈来不及进
树——PUCT 退化成「按先验顺序枚举可走点」，访问分布近似均匀。于是自对弈等于随机落子，
策略损失只能收敛到「均匀分布的熵」这个地板，症状看起来正是「训练不收敛」：ce 卡住
不动、mse 反弹、评估得分在 0.3~0.55 之间乱跳。

实测证据（9x9、sim128 + batch128 那次跑到第 5 轮）：

- 每步搜索只有 2 次前向（根 1 次 + 一批 127 个叶子），根孩子的访问数全为 1；sim 大于
  可走点数时还有 46/127 个叶子被重复入队，白花算力并把 N/Q 算重；
- 落库的策略目标里 83% 的样本最大概率 < 0.05；前 20 手的目标熵与 ln(合法点数) 完全
  重合（4.36 / 4.36、4.20 / 4.23），也就是纯均匀；
- 相邻几轮的目标熵按手数分档几乎一模一样（4.36/4.20/3.61/2.68/1.71），数据分布从第 1
  轮起就没动过；ce 稳定在 3.54~3.56，恰好等于这批均匀目标的平均熵 3.49——多余损失为
  0，网络已经学到头了，学到的却是随机落子。

现在 `mcts.clamp_batch` 按 `SEARCH_BATCH_ROUNDS`（默认 8）把 batch 兜底收紧到
`sim // 8`，训练日志首行会打印实际生效值；`tests/test_core.py` 的 `mcts_batch_guard`
守住「多轮回传 + 同一叶子不重复入队 + 树深 > 1」。自对弈/评估/对战/提示四条路径都走
同一个 `mcts_search`，改这一处即可全部生效。

### 数据体检 `check_data.py`

不收敛时先分清是「标签没内容」还是「网络没学动」，这两个指标各管一头：

- `uv run python check_data.py runs/<dir>`（可加 `--iters 1-8`）逐轮打印下表并给判定；
- `gap = ln(合法点数) - H(策略目标)` —— **搜索质量**。判定只看开局档（前 20 手）：
  残局可走点本来就少、战术强制掩码又会把目标压成一两点，看全盘均值会被骗过去。
  `gap < 0.2` 就是随机落子，先去查 `mcts_batch` 与 `sim_selfplay` 的关系；
- `ce - H(训练窗口)` —— **还剩多少可学**。`ce` 取自 `meta.json`，`H` 按
  `buffer_window` 拼同一批数据算。差值 <0.05 说明网络已经把标签学干了，加训练步数
  只是拟合噪声；差值很大（>0.5）才轮到怀疑 lr/步数/网络容量；
- `maxP`（目标最大概率均值）、`unif`（最大概率 <0.05 的样本占比）、`draw`（z=0 占比）
  用来盯趋势：搜索修好之后 `unif` 应当逐轮往下掉，`draw` 也应从 ~25% 回落。

那次 5060 的 run 用这个脚本看到的是：开局档 `gap=0.02`、`unif=85%`、`ce-H≈0.05`，
三件事一起指向「标签是均匀的、且已经被学干了」。

## 界面说明

- 图形窗口（默认）：木格棋盘上点击落子，红点标记最后一手，虚线圈跟随鼠标预览。
  命令行参数只是初始值，全部可在面板内改：
  - 模式单选：人机对战 / 人人对弈录制 / 观战 vs 随机 / 观战 vs 模型
    （人人录制不加载模型，双方点击轮流入库，面板显示当前轮到黑/白）
  - 「加载模型…」「对手模型…」文件选择器，换模型自动重开一局
  - 执子下拉框、搜索深度滑条（实时显示数值）
  - 胜率预判条：AI 每次搜索后显示它的自估胜率；你走完棋后 AI 会用小深度
    即时推演一次刷新（观战模式则显示下一手方的预测胜率）
  - 按钮：新局 / 悔棋 / 提示 / 认输（人机），▶自动 / 单步 / 间隔滑条（观战），
    5局统计（当前模型 vs 当前对手连下 5 局，弹窗出成绩）
- 控制台模式（`--cli`）：字符棋盘，输入 `E5`（或 `5e`、`5,5`）落子，
  命令 `undo` 悔棋、`hint` 推荐、`resign` 认输、`quit` 退出。
  `--cli --self` 进入控制台人人录制（无 hint，双方轮流入库）。

## 战术强制与冷启动数据

- **强制手掩码**：搜索前先用规则引擎检测战术点——己方一手可成五则只搜胜点，
  对方一手可成五则只搜堵点（自对弈/对战/评估全生效）。这让早期网络不再出现
  "该堵不堵"的瞎眼棋，相关样本同时写进训练分布，策略头会逐步内化这类常识。
- **人人对弈录制（冷启动首选）**：GUI 模式选「人人对弈录制」，或命令行
  `uv run play.py --self`（控制台版 `--cli --self`）。双方着法都由人输入，
  全部以 one-hot 策略 + 真实胜负 z 存入 `runs/<dir>/buffer/human/`，
  永久参与训练窗口（不受 `--buffer-window` 淘汰），不经过任何网络权重。
  误触短局（<6 手）与悔棋后的局自动丢弃。
- **人机对局记录（谨慎使用）**：人机模式勾选「本局存入人类数据集」时，AI 一侧
  的 π 用的是当前网络的 MCTS 访问分布——网络还很弱时这些是噪声，会污染冷启动
  数据，早期建议取消勾选或直接用人人录制代替。
- **规则老师（可选批量生成）**：`uv run python -m gobang.teacher --games 600
  --out runs/<dir>/buffer` 用启发式窗口评估自对弈批量造数据（战术 sanity、
  对随机 100% 胜），写入同一 human/ 池，适合不想手动下够量时用。
- `--human-epochs N`：每轮额外把 human 池数据单独快训 N 遍，冷启动期建议 15~25；
  蒸馏够几轮后设 0 恢复纯自对弈（默认 0）。

## 实现结构

```
gobang/
  config.py    # 常量、PRESETS 预设、train.json 参数文件加载、全部超参默认值
  game.py      # 位棋盘规则引擎（哨兵位防跨行误判，win 检测 O(1)）
  model.py     # 轻量 CNN：conv_in + 6×残差块 + 策略头/价值头
  mcts.py      # PUCT：叶子批量送网络评估（pend 标记防重复入队 + batch 兜底收紧）
  agent.py     # 特征编码 + 推理封装（己方/对方/上一手/先手 4 平面）
  selfplay.py  # 多进程自对弈/评估：任务提交-收集两段式，可与训练跨轮重叠
  dataset.py   # 每轮 npz + 窗口加载 + D4 对称增强 + GameRecorder 对局录制
  teacher.py   # 启发式规则引擎（窗口评估+双四识别），冷启动数据批量生成
  trainer.py   # 训练循环（CE+MSE，非法点屏蔽，可开 AMP 混合精度）与 match 评估
  ui.py        # 字符棋盘渲染与坐标解析
main_train.py  # 迭代主循环：自对弈 -> 训练 -> 评估晋升（评估与下一轮重叠）
play.py        # 人机 / 人人录制(--self) / 机器vs机器 / 统计模式
check_data.py  # 自对弈数据体检：策略目标熵/gap/ce-H，判断标签有没有信息
train.json     # 默认参数文件（--config 可另指定，train_5060.json 为 5060 长跑配置）
tests/test_core.py  # 自检：胜负、MCTS、增强、UI、参数优先级、AMP（python tests/test_core.py）
```

训练产物在 `runs/<name>/`：`best.pt` `latest.pt` `meta.json`（每轮指标）、
`buffer/*.npz`（对局数据）、`tb/`（tensorboard 日志）。
